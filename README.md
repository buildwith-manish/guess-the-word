# Guess the Word by Emoji — Remotion + GSAP (Pattern 1)

A 50-question "guess the word from two emoji" quiz, rendered frame-perfectly
with **Remotion**. GSAP is used only for its **easing math** (Pattern 1: pure
functions in → numbers out, **no GSAP timelines**). Look, timings and copy
follow the reference `quiz_short_hook.html` (1280×720 stage, scaled 1.5× to
the 1920×1080 design canvas). **Output is 2560×1440 (1440p) at 60 fps.**

```
hook intro → EASY ×20 → bonus → MEDIUM ×15 → bonus → HARD ×15 → scoreboard → end screen
            6s each                                   7s each          8s each
```

Runtime: **15:43** (28 283 design frames at 30 fps = 56 566 output frames at 60 fps).
The composition length is derived from `settings.json` + `questions.js` — never typed by hand.

### 1440p / 60 fps

- Everything is still **authored in 30 fps design frames on a 1920×1080 canvas**, so no timing,
  easing or sound cue changed. The composition runs at 60 fps and `src/clock.ts`
  (`useDesignFrame`) converts each output frame back into a fractional design frame, so every
  animation is sampled twice as often at identical speed.
- **1440p** is Remotion's output scale (`settings.output.width / settings.width` = 4/3, set in
  `remotion.config.ts`): same layout, rendered at a higher pixel density, so text and vector
  art are crisp. Output is H.264, `yuv420p`, CRF 18.
- Audio is placed by `<Sequence>`; `Soundtrack.tsx` multiplies every offset by `TIME_SCALE`
  and interpolates the music-duck envelope for 60 fps.
- Output size/fps live in `settings.json → output`. Photos are 1920×1080 (`settings.images`),
  so they are never upscaled at 1440p; `npm run images:hd` re-fetches every photo and only
  accepts sources of at least 1920×1080 (anything smaller is reported as "soft").
- Rendering is roughly 2× the frames at ~1.8× the pixels per frame — expect a long render.
  `GTW_CONCURRENCY=4 npm run render` overrides the default concurrency of 2.

## Install

```bash
npm install          # also regenerates src/rounds.json from questions.js
```

Node 18+. Remotion downloads its own headless Chromium on the first render.
`ffmpeg` is only needed by the optional image pipeline (the static build in
`node_modules/@remotion/compositor-*` is picked up automatically).

## Dev

```bash
npm run dev          # remotion studio
```

Because no animation keeps internal state, the timeline scrubs both ways and
every frame can be rendered in any order.

## Render

```bash
npm run render                  # out/video.mp4 (single pass, Remotion parallelises)
npm run render:lanes            # same video, 1800-frame chunks (30 s @ 60 fps)
npm run render:batches -- --size 600
npm run still                   # out/still.png  (output frame 1400 = 23.3 s)
npm run timeline                # print the real frame plan
```

### Resume-safe batches

`scripts/render-batches.js` can split the video into chunks, render each with
`remotion render --frames=a-b`, record finished chunks in
`out/.render-progress.json`, and remux them losslessly (`-c copy`) into
`out/video.mp4` once the last one lands.

```bash
node scripts/render-batches.js --lane         # one full render (default)
node scripts/render-batches.js --size 600     # 600-frame chunks (≈10s each at 60 fps)
node scripts/render-batches.js --only 12      # one worker: only chunk 12
node scripts/render-batches.js --concat       # just remux what exists
node scripts/render-batches.js --clean        # wipe chunks + progress
node scripts/render-batches.js --force        # redo everything
```

Kill it at 92 %, run the same command again: finished chunks are skipped.
Flags after `--` are forwarded to `remotion render` (e.g. `--concurrency=4`).

## Questions & timings

| file | what it controls |
| --- | --- |
| `questions.js` | the question bank — `id, word, clueA, clueB, level, split` (clue PNGs live in `public/emoji-icons/`) |
| `facts.csv` | fact library, `word,fact` — fills any `questions.js` entry whose `fact` is empty |
| `src/rounds.json` | generated by `npm run data`; git-ignored |
| `settings.json` | fps, size, per-level clock, level card length, hook length, bonus rounds, end-screen copy, all UI strings |
| `src/timing.ts` | turns both files into an exact frame plan used by every scene |
| `src/bonus-engine.ts` | the five seed-generated bonus rounds |

Two free letters flip **while the clock runs**, each together with a 💡 bulb: the
first letter at 2/3 of the time left, then the letter at position `reveal` at
1/3 left. `reveal` is a **0-based** position (3 on `STARFISH` = the R, the same
digit the reference HTML calls `SPLIT`); `0` means no second free letter. All
other letters flip when the clock ends. `fact` is optional and shows on every `factEvery`-th question
(`settings.json → timing.factEvery`).
A row with an empty `fact` falls back to `facts.csv`, which already covers the
50-word set from `public/emoji-icons` (Raincoat … Hogwash) plus the current five,
so a new word gets its fact card without touching `questions.js`. Keep facts to
**8 words or fewer** — the voiceover reads them in the card's hold time
(`npm run data` warns above that).

After editing the CSV:

```bash
npm run data                # questions.js  ->  src/rounds.json
npm run timeline            # sanity-check the new length
```

Levels come from the `level` column (`EASY`/`MEDIUM`/`HARD`); each level block
gets its own card and its own clock length (`settings.json → levels[].time`).

## Images

Photos are optional: an empty `src/image-manifest.json` makes every answer card
render the `IMAGE HERE` placeholder, like the reference HTML did.

```bash
npm run images             # scripts/fetch-images.js — z-ai image-search CLI
npm run images:resize      # scripts/resize-images.js — ffmpeg → 1920x1080
npm run images:refetch     # scripts/refetch-broken.js — repair missing/broken
npm run images:all         # all three, in order
```

* `fetch-images.js` calls `z-ai image-search "<word> photo" --count 5 --json`
  and **rejects anything from `shutterstock.com`** (plus `sscdn.co`,
  `shutterstock.net` and a few other stock hosts listed in
  `settings.json → images.blockedHosts`). Override the binary with `--bin` or
  `Z_AI_BIN`, the query with `--query`, the CLI flags with `--cli-args`. Progress
  is checkpointed to `scripts/.image-progress.json` (git-ignored) and re-runs
  are safe.
* `resize-images.js` normalizes to exactly **1920×1080** with
  `scale=...:force_original_aspect_ratio=increase,crop=1920:1080` (lanczos). It
  uses `ffmpeg` from PATH, `$FFMPEG_BIN`, or the static binary inside
  `node_modules/@remotion/compositor-*`.
* `refetch-broken.js` validates every file (exists, >12 KB, real image header,
  correct dimensions) and repairs only the bad ones — `--dry-run` to report.

A question shows a photo only if its id is listed in `src/image-manifest.json`.

## Colour changes

Like the HTML, **every question has its own backdrop** (`settings.json →
levelThemes`, cycling per question) and bonus rounds sit on an orange one
(`bonus.theme`). Between scenes an `iris` segment wipes the next colour in from
the centre with a whoosh (`timing.irisFrames`, ≈0.85 s, same curve as the HTML),
so the runtime grows by one wipe per transition.

## Reminder pop-up

After the questions listed in `settings.json → reminder.after` (default `[10, 25, 40]`,
as in the HTML) a short "Still counting? ❌" pill pops up (`src/Reminder.tsx`,
`reminder.frames` ≈ 1.7 s, text in `text.reminder`). The default 5-question cut
never reaches Q10, so it only shows once the bank is longer — set e.g. `[3]` to
preview it.

## Sound

The reference HTML makes all of its sound live with WebAudio. A rendered video
can't do that, so `scripts/generate-audio.js` ports the same synth to WAV files:

```bash
npm run sounds      # -> public/sounds/*.wav + src/sound-manifest.json (deterministic)
```

* **SFX** — whooshes, pops, timer ticks, free-letter chimes, letter flips,
  answer stamp + arpeggio, boom hits, heartbeat, siren, drumroll, jingles.
* **Music** — a 112.5 BPM loop in three phase-locked layers (`music-base`,
  `music-l1`, `music-l2`), each exactly 256 frames, so it loops without drift.
  Layers fade in as the quiz gets busier (the HTML's `[0,1,1,2,2]` ramp, spread
  over however many questions there are) and duck under every SFX.
* **Wiring** — `src/sound.ts` turns the timeline into frame-accurate cues,
  `src/Soundtrack.tsx` mounts them as `<Sequence><Audio/></Sequence>` pairs, so
  chunked renders (`render-batches.js`) stay deterministic.
* **Settings** — `settings.json → sound`: `enabled`, `sfxGain`, `musicGain`
  (baked into the WAVs; re-run `npm run sounds` after changing them).
  Want your own sounds instead? Overwrite the files in `public/sounds/` with the
  same names.

## GSAP Pattern 1 in this project

> **GSAP provides easing math via pure functions, Remotion renders frames, no
> GSAP timelines.**

`src/gsap-helpers.js` compiles GSAP eases once and exports them as pure
functions:

| helper | GSAP ease | used for |
| --- | --- | --- |
| `backOut` | `back.out(1.7)` | emoji seats, cards, score rows, chips |
| `expoOut` | `expo.out` | reveals, letter blanks, rules, hairlines |
| `elasticOut` | `elastic.out(1, 0.35)` | answer stamps, badges, caption chips |
| `power3Out` / `sineInOut` | … | slams, breathing glows |
| `cubicBezier(.65,0,.25,1)` | CSS curve from the HTML | the iris colour wipe (`anim.ts → irisEase`) |
| `linear` | none | the clock fill only — an eased countdown lies |

`src/anim.ts` is the only bridge between the two worlds:

```ts
const p = prog(frame, start, 18, backOut);   // pure: frame → eased 0..1
style.transform = `translateY(${(1 - p) * 160}px)`;
```

No `gsap.timeline()`, no `gsap.to()`, no `useEffect`, no animated refs. That is
why any frame renders in isolation, the Studio scrubs perfectly in both
directions, and re-renders are identical frame for frame (all randomness is
seeded).

## Notes

* Fonts are bundled and loaded through `@remotion/fonts`, including a colour
  emoji face, so a render never depends on the machine's installed fonts.
* All copy — hook headlines, chips, scoreboard, end screen — lives in
  `settings.json`, so you can re-skin the video without touching a component.
* The reference HTML's WebAudio score is rendered to WAV files by
  `scripts/generate-audio.js` (Remotion mixes audio from files, not oscillators).
